1. OVERVIEW / PURPOSE
================================================================================
SkillMap is a demand-driven learning platform that reads live market demand for
marketing skills, turns it into an explorable heatmap, and lets users learn those
skills end-to-end through structured video courses.

Core idea:
  - See which skills the market wants most (skill map heatmap).
  - Pick a skill and discover attached courses.
  - Enroll, work through video lessons at your own pace, track progress, and
    review courses.
  - Admins can create, edit, and delete courses and their lessons.

3. DATA MODEL (PRISMA SCHEMA)
================================================================================

  User
    id, email (unique), name, passwordHash, role (ADMIN | STUDENT), avatarColor
    enrollments[], reviews[]

  Skill  (47 skills, demand-driven, the heart of the app)
    id, name (unique), slug (unique), category, demandScore (0-100), description,
    color
    courses[]

  Course  (published courses that teach a skill)
    id, title, slug (unique), headline, description, level, durationMin,
    imageUrl?, imageColor?, status ("Published"), category?, createdAt, updatedAt
    skillId? -> Skill (SetNull on delete)
    lessons[], enrollments[], reviews[]
    (price was dropped — see migration 20260831000000_remove_course_price)

  Lesson  (ordered steps inside a course)
    id, title, durationMin, content, videoUrl?, order, courseId -> Course (Cascade)
    completions[] ; @@unique([courseId, order])

  Enrollment  (user ↔ course, the learning contract)
    id, progress (0-100), enrolledAt, completedAt?, userId -> User (Cascade),
    courseId -> Course (Cascade), completions[]
    @@unique([userId, courseId])

  LessonCompletion  (marks one lesson done inside an enrollment)
    id, lessonId -> Lesson (Cascade), enrollmentId -> Enrollment (Cascade),
    completedAt
    @@unique([enrollmentId, lessonId])

  Review  (one user's rating + optional comment on one course)
    id, rating (1-5), comment?, createdAt, userId -> User (Cascade),
    courseId -> Course (Cascade)
    @@unique([userId, courseId])

================================================================================

  3d. Course <-> Skill coverage (many-to-many)
      A course is filed under ONE primary skill (Course.skillId) but usually
      teaches several. The join table "_CourseCoveredSkills" (migration
      20260831120000_course_covered_skills) records the secondary skills each
      course covers; the mapping lives in prisma/course-skills.ts as
      COURSE_COVERS, keyed by course slug and listing skill NAMES.
      Without this every skill showed exactly one course. With it the median
      skill has ~4 courses (183 coverage links across 54 courses).
      - getSkills()/getSkillBySlug() report _count.courses as
        primary + covering, so the map and skill pages show the real total.
      - getCoursesBySkill() returns primary OR covering matches, dedicated
        course first.

  3e. Course images
      Course.imageUrl holds a verified Unsplash CDN URL; the mapping lives in
      prisma/course-images.ts (COURSE_IMAGES by slug, plus THEME_POOL of spare
      verified images grouped by theme). next.config.ts allows
      images.unsplash.com via images.remotePatterns.

  3f. Lesson duration
      Lesson.durationMin is derived from the real length of its YouTube video
      (scraped lengthSeconds, rounded to minutes), and Course.durationMin is
      the sum of its lessons - so the stated duration always matches what the
      learner actually watches. Policy: no video under 5 minutes (no
      short-form/Shorts), target 10-15 minutes, longer only sparingly.
      See VIDEO_AUDIT.md for the audit trail.

9. SKILL PAGES & SKILL MAP
================================================================================

  9a. Skill Detail — /skill/{slug}
      Behind requireAuth() + rendered with <AuthedHeader> (this page sits
      behind the auth middleware, so it is not a <PublicNav> page).
      Breadcrumb "Skill map", demand-tier badge, skill name, description.
      Demand score (/100), rank among mapped skills, territory name (in the
      description text).
      Stat tiles: related-course count, enrolled learners (sum of course
      popularity for that skill's courses).
      "Courses for {skill}" grid of <CourseCard>.
      "Where {skill} sits on the map" — <SkillTerritoryMap> with that skill
      highlighted (activeSlug).

  9b. Skill Territory Map — <SkillTerritoryMap>
      Heatmap visualization of all skills sized/colored by demand.
      Each skill is a circle; territories are grouped by category.
      Tooltip/title shows demand score. In light mode uses multiply blend
      and light background.
      Clickable/selectable — clicking a skill shows its courses and links.

================================================================================

  9c. Skill map navigation model
      There is ONE page that shows a skill in full: /skill/[slug]. It carries
      the map (left), the skill panel (right) and the courses that teach the
      skill (below). Every skill node on every map is a <Link> to
      /skill/[slug], so choosing another skill is a real navigation and the
      panel can never show stale content. /dashboard/skill-map is the browse
      entry point: the same map, with an empty-state panel.
      Both surfaces render through SkillMapStage, which owns the frame (map +
      320px panel) and the "+N more" territory listing, so the map is the same
      size on every page and that affordance works everywhere.
      The map's own chrome (zoom controls, legend) sits at z-20 so the sticky
      site header (z-40) always paints above it.

11. AUTHENTICATION & AUTHORIZATION
================================================================================

  - Auth lib (src/lib/auth.ts):
      signup(name, email, password) — bcrypt hash(12), db.user.create,
        createSession, redirect /dashboard.
      login(email, password) — bcrypt.compare, rate-limited (10/10min),
        createSession, redirect /dashboard.
      logout() — deleteSession, redirect /login.
      updateProfile(name) — update user name.

  - Session lib (src/lib/session.ts):
      createSession(userId, role) — JWT HS256, httpOnly cookie "session",
        7-day expiry.
      decrypt(session) — jwtVerify -> { userId, role, expiresAt }.
      deleteSession().

  - Auth guard (src/lib/dal.ts):
      requireAuth() — decrypt session + db.user.findUnique; redirects /login.
      requireAdmin() — requires role ADMIN; redirects /dashboard.
      verifySession() — cached.

  - Middleware (src/proxy.ts):
      PUBLIC_PATHS = ["/", "/login", "/signup"].
      Non-public, non-static, non-API routes: redirect to /login if no session;
      redirect signed-in users off /login & / to /dashboard.
      Matcher: everything except /api, _next/static, _next/image, static images.

12. CORE BUSINESS FLOW (USER JOURNEY)
================================================================================

  1. DISCOVER   — Land on / skill map heatmap or browse /dashboard/browse.
  2. PICK       — Click a skill on the map -> /skill/{slug} to see courses.
  3. ENROLL     — On /courses/{slug}, click "Enroll now" (-> enroll()).
  4. LEARN      — Go to /courses/{slug}/learn; watch video/text lessons;
                  click "Mark complete" (toggleLessonComplete).
  5. TRACK      — Progress bar, % complete, lesson counter, My Courses.
  6. COMPLETE   — When all lessons done, "Course complete" -> /courses/{slug}.
  7. REVIEW     — On course page, leave a rating + comment (reviewCourse).
  8. MANAGE     — Admins create/edit/delete courses & lessons via /dashboard/admin.

13. KEY SERVER ACTIONS & DATA HOOKS
================================================================================

  Data hooks (src/lib/data.ts, server-only):
    listCourses(filters?)  — paginated published courses with search/sort.
    getCourseBySlug(slug)  — full course + lessons + reviews + avgRating.
    getSkills()            — all skills ordered by demandScore.
    getSkillBySlug(slug)   — single skill.
    getCoursesBySkill(s)   — published courses for a skill.
    getMyEnrollments()     — current user's enrollments + course summaries.
    getRecentEnrollments(u,take) — in-progress enrollments for dashboard.
    getCategories()        — distinct published course categories.
    getPlatformStats()     — { skills, courses } counts.
    getSkillOptions()      — skill id/name/category for admin dropdowns.
    getPopularCourses(t)   — top courses by enrollment.
    getMyEnrollmentForCourse(u,c) — enrollment record.
    getCourseForLearning(u,slug) — course + lessons + done set for learning.
    getAdminCourses()      — all courses for admin table.
    getCourseForEdit(id)   — course + lessons + skill for edit page.
    getProfileData(u)      — user + review history + stats.

  Server actions (src/lib/courses.ts, "use server"):
    createCourse(form) / updateCourse(id, form) / deleteCourse(id)
    addLesson(courseId, form) / updateLesson(id, form) / deleteLesson(id)
    enroll(courseId)
    toggleLessonComplete(lessonId, courseId)
    reviewCourse(courseId, form)

  Auth actions (src/lib/auth.ts):
    signup / login / logout / updateProfile

16. RUNNING THE PROJECT
================================================================================

  Dev server:
    npx next dev            (Turbopack, port 3000)
    PORT=3000 npx next dev -p 3000

  Build & typecheck:
    npx tsc --noEmit
    npx eslint
    npm run build

  Seeding data:
    npx tsx prisma/seed.ts
    Course.durationMin is now derived by summing its lessons' durations
    (no per-course durationMin literals in the seed data), so the hero
    figure and the curriculum subtotal always agree.
    Lesson videos come from prisma/lesson-videos.ts (takes precedence over
    inline seed ids); it was re-audited against the real YouTube oEmbed API
    and 38 of 202 lesson videos were replaced with verified, topically
    relevant ones — see VIDEO_AUDIT.md for the full replacement log.

  Environment:
    .env at repo root:
      DATABASE_URL="file:./dev.db"
      SESSION_SECRET="<64-char base64>"
    Runtime DB: dev.db (repo root).
